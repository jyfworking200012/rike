# 《日课》

把现实作息打卡转化为文本肉鸽冒险的资源引擎。

**一句话**：现实里多自律一天，游戏里的世界就大一分。

设计依据见 `docs/GDD.md`（v0.2）。本目录是第一版实现。

---

## 怎么在手机上用

### 方案 A：局域网（临时、最快）

电脑上在本目录执行：

```bash
python -m http.server 8000
```

手机连同一个 WiFi，浏览器打开 `http://<电脑IP>:8000`，然后：

- **iOS Safari**：分享 → 添加到主屏幕
- **Android Chrome**：菜单 → 添加到主屏幕

加完之后从主屏图标进入，全屏运行，与 App 无异。

> 注意：这种方式只在同一 WiFi 下有效，换网络就打不开。

### 方案 B：静态托管（✅ 已部署，2026-10-08）

已推送到 GitHub Pages，线上地址：

**https://jyfworking200012.github.io/rike/**

手机浏览器打开这个地址，然后：

- **iOS Safari**：分享 → 添加到主屏幕
- **Android Chrome**：菜单 → 添加到主屏幕

加完之后从主屏图标进入，全屏运行，换网络也能用。

仓库：https://github.com/jyfworking200012/rike （public，数据在各自浏览器本地，公开 URL 无隐私风险）。
后续更新：改完 `index.html` 后 `git add . && git commit -m "..." && git push` 即自动重新部署（1-2 分钟生效）；
若改了 `sw.js`，记得把文件内 `CACHE` 版本号 +1，否则旧缓存可能不刷新。

### 方案 C：只看不用

直接把 `index.html` 发到手机，用浏览器打开也能玩，但无法添加到主屏幕，且部分浏览器对本地文件限制较多。不推荐。

## 数据存在哪

全部记录存在**手机浏览器本地**（localStorage），不联网、不上传、无后端。

**因此有一件事必须注意**：清除浏览器缓存 / 数据会丢失全部记录。请在「兑换」页底部定期用**导出数据**把文本存到备忘录或微信文件传输助手。换手机时用**导入数据**恢复。

### 顺手修掉的真 bug

连击满 7 天的里程碑词条：原代码 `grantTrait(pick(pool))` 与提示文案各掷了一次随机，
**显示的名字和实际获得的词条可能不是同一个**。已改为掷一次、共用结果（有回归测试）。

### 第一版刻意没做

- **支线任务**（现实他人交付的任务）——需要额外的录入与周上限计数模块，押后
- **AI 文本渲染**——按 GDD 附录 A 的路线，必须在骨架版通过 14 天观察窗之后才接
- 多地图（远行 / 荒野 / 档案馆 / 长夜）——解锁表里已列出，但内容未开发，界面上标了「内容开发中」
- 云同步、社交、排行榜、成就系统
- 美术资源（刻意保持纯文本 + 极简排版）

## 核心规则速查

**打卡产出**：每项 +1 精力 / +1 积分 / +1 对应属性。附照片则该项积分 ×1.5（可选，不附无惩罚）。

**满勤**（7/7）：额外 +1 精力 / +5 积分，连击 +1。

**精力**：上限 6，每次冒险消耗 3。溢出的精力按 2:1 折算成积分。

**连击系数**（只作用于积分，不影响精力）：

| 连续满勤天数 | 积分倍率 |
|---|---|
| 1-6 | ×1.0 |
| 7-13 | ×1.2 |
| 14-20 | ×1.5 |
| 21+ | ×2.0 |

**免死金牌**：上限 3 张。每连续 7 天全勤赠 1 张。未满勤当天自动消耗 1 张，连击不清零；没有金牌则连击归零，并触发**重建期**（原连击 ≥3 时）：3 个自然日内打卡积分 ×1.5。

**撤销**：当日未满勤时可撤销任意已打卡项（按实付记录回滚）；满勤结算涉及连击/金牌/词条，不可撤销。

**红线**：任何情况下不清零属性、积分、词条。

**冒险判定**：选项门槛 ≤ 当前属性 → **必定成功**（不掷骰子）。门槛 > 属性 → 越级尝试，成功率 = 属性 / 门槛，失败扣 4 定力（普通失败扣 2）。每个事件都有至少一个无门槛保底选项，不会卡死。

**结算**：定力归零 → 已通过节点 × 2 分。走完 6 节点 → 6×2+10 = 22 分。深入成功 → 7×2+20 = 34 分 + 15% 掉落永久词条。

## 自检

改完代码后跑一遍：

```bash
node selftest.cjs
```

覆盖 167 项断言：数据完整性、连击系数边界、精力溢出折算、满勤与免死金牌、
断链保护、**重建期**、**撤销回滚精确性**、**掉落防刷**、**每日一句确定性**、
徽章与音效降级、门槛判定（含 300 次重复验证"门槛内无随机失败"）、词条加成、
run 全流程、失败结算、渲染层 HTML 产出、脏数据健壮性、函数完整性与死按钮检查。

结论写在 `_test_out.txt`。

## 已知边界（诚实声明）

1. **所有数值都是推算的，没有经过真人验证。** GDD 里标了 P1-P14 共 14 项待验证参数，实现时按 GDD 取值，但都还没有实测依据。
2. **首个观察窗口是 14 天，重点是第 8-10 天。** 那是历史失败点，也是这套设计真正要验证的地方。
3. **事件骨架有 30 个，但组合可能重复。** 同一局内不会重复，但连续几局会遇到熟面孔。GDD 第 9 节把「连续 3 次 run 遇到重复事件」定义为内容枯竭的失败信号，需要盯着。
4. **免死金牌上限 3 张是从 GDD 取的推算值**，可能过松或过紧。
5. 未在真机（iOS / Android）上实测过，只在桌面浏览器逻辑层验证。
