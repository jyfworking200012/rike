# 《日课 · 一亩三分地》

一个自己用的、手机上打卡的院子。

**一句话**：打卡不是攒代币去消费，打卡就是在自己的院子里动一下手。

线上：https://jyfworking200012.github.io/rike/

---

## 为什么改成这样

上一版（v1）是「打卡 → 攒精力 → 玩一局随机事件 → 攒积分 → 换奶茶」。真实数据跑了 11 天，结论是这套东西不成立：

| 数据 | 说明 |
|---|---|
| 打卡率 33.8%（26/77） | 七项门槛高于实际基线 |
| 一局肉鸽共 6 次，全部集中在前 2 天 | 游戏层在 48 小时内被放弃 |
| 兑换 1 次后再无第二次 | 能随时买到的消费品，不构成奖励 |
| 最长的连击机制触发 0 次 | 所有正反馈都建立在「满勤」上，从未发生过 |

根因不是「不够好玩」，是**结构错了**：那套设计本质是「打卡付费玩一次老虎机」。代币和老虎机之间没有因果，所以获得感是假的。

v2 换范式：

| | v1 | v2 |
|---|---|---|
| 打卡的意义 | 换取代币 | 直接改变院子里的东西 |
| 成长载体 | 数字（积分/属性/词条） | 画面（树、墙、井、石阶、灯） |
| 门槛 | 7 项全勤 | **任选 3 件** |
| 失败代价 | 连击归零 + 系统压力 | 只影响连击，**院子一块砖都不少** |
| 长期目标 | 攒够兑换 | 院子越住越像样 |
| 认知负担 | 9 个概念 | 0 个数值 |

## 七件事 → 院子里的七样东西

| 做的事 | 院子里发生什么 | 长期累积成 |
|---|---|---|
| 按时起床 | 门前多垒一级石阶 | 台阶越高，门越像个门 |
| 出去锻炼 | 院角的树长高一寸 | 从树苗长到有树冠 |
| 洗个澡 | 井里的水涨一寸 | 井水由浅到满 |
| 学点东西 | 窗内多一本书 | 窗台堆满书 |
| 戒断打卡 | 院墙添一块砖 | 墙从缺口到厚实 |
| 看闲书 | 廊下再添一本 | 廊下有了一小摞 |
| 准点睡觉 | 屋顶补好一片瓦 | 屋顶由漏到严实 |

**达成当天，门边的灯会亮，天色变暖。** 这是唯一的「通关反馈」，没有数字。

## 远行（每周一次）

补给 = 最近 7 天的达成天数。三段路，每段两个选择：

- **稳妥**：消耗 2 点补给，必定走通
- **冒险**：消耗 1 点，可能走通也可能退回

走完三段带回一件院子里的纪念物（挂在墙上）。补给不够可以折返，**院子不会因此少一块砖**。

## 三条设计纪律

1. **院子永不清零**。断一天只影响「连着几天」。
2. **门槛低于基线**。3 件，最差的一天也做得到。
3. **界面不出现难度数字**。没有成功率、没有属性值、没有积分。

## 本地跑

```bash
cd rike
python -m http.server 8000
# 打开 http://localhost:8000
```

手机：浏览器打开线上地址 → 分享 → 添加到主屏幕。

## 自检

```bash
node selftest2.cjs
```

覆盖：数据结构、打卡计数、门槛判定、院子成长参数与上限、
断链不清零、连击累加与重置、渲染层 HTML 产出、远行流程、
补给不足时的折返出口、导出导入往返、脏数据健壮性、本地时区日期。

## 数据

只存在手机浏览器本地（`localStorage`），不上传任何地方。
「其他」页底部可导出 / 导入 JSON。

**别删主屏图标再重加**（iOS 会连数据一起删），**别清网站数据**。
