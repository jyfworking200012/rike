# 设计稿 v9：图画素材清单与开源引入

> 一句话：**画面里 92% 的面积没有开源素材可用，只有 8% 的图标能引——而那 8% 恰好是最能提升"细节感"的部分。**
> 状态：设计稿，未写代码。

---

## 一、先清点：画面到底由哪些素材构成

`index.html` 现在 54,503 字节，全部画面是 6 个 SVG 函数画出来的：

| 函数 | 画什么 |
|---|---|
| `townSVG()` | 场景总装：天空、地面、路、远山、人、烟、灯 |
| `houseSVG()` | 房屋（参数化：墙色 / 屋顶 / 窗 / 亮灯） |
| `wellSVG()` | 井 |
| `granarySVG()` | 粮仓 |
| `shrineSVG()` | 祠堂 |
| `towerSVG()` | 灯塔 |

按**画面面积**拆（估算，按 390px 视口一屏计算）：

| 层 | 内容 | 占画面面积 | 现在怎么来 |
|---|---|---:|---|
| 场景层 | 天空、地面、路面、远山、远景屋顶 | 30% | 手绘色块 + 曲线 |
| 建筑层 | 破屋 + 井/粮仓/铁匠铺/集市/祠堂/灯塔，含等级变化 | 32% | 6 个手绘函数 |
| 人物层 | 18 个火柴人 | 15% | 1 个模板 + 颜色/姿态变化 |
| **图标层** | **木、石、肉、布、铁、钱、药、文化、治安（9 个）** | **8%** | **现在只是小圆点 + 文字** |
| 界面层 | 底栏、卡片、按钮、结算行、文字 | 15% | CSS |

**关键事实：图标层现在是全画面最弱的一层。** 九个资源全靠一个彩色小圆点加两个字表达——这是"看不懂"的直接来源之一。

## 二、三档：能引 / 要自己画 / 不能引

| 档 | 内容 | 结论 |
|---|---|---|
| ✅ **能引（开源）** | 资源图标 9–12 个、UI 图标（设置/导出/刷新） | 引。体积小、风格契合、收益最大 |
| 🔧 **要自己画** | 建筑 7 座、人物、天空地面 | 没有能用开源素材，继续手绘，但要做厚 |
| ⛔ **不要引** | 纸纹、材质贴图 | 改用 SVG 滤镜程序生成，零 KB |

---

## 三、能引的那一档：game-icons.net（实测数据）

`game-icons/icons`，1,361 星，**4,313 个图标**，纯黑单色线描。

我实测下载了几个核对体积：

| 图标 | 体积 |
|---|---:|
| `lorc/stone-tower.svg` | 685 B |
| `lorc/meat.svg` | 2,229 B |
| `delapouite/coins.svg` | 6,810 B |

**平均 2KB 左右。9 个资源图标 ≈ 18KB，加上 UI 图标 4 个 ≈ 26KB。**

现在整个 `index.html` 是 54KB，加 26KB 变 80KB —— 单文件 PWA 完全扛得住。

**为什么它和纸墨风最搭**：它是**纯黑填充剪影、无渐变、无描边粗细变化**。这种图正好可以 `<use>` 进来后 `fill: currentColor` 染色，白天用墨色、夜里用暖金，一套图两种主题。

**许可**（README 原文）：

> Icons provided under the Creative Commons 3.0 BY or CC0 if mentioned below.
> Each sub-folders correspond to a different contributor.

**这意味着：大部分要署名（CC BY 3.0），部分是 CC0。**

处理方式很简单——在设置页底部加一行：

```
图标：game-icons.net（Lorc, Delapouite, ...）· CC BY 3.0
```

这只是自用游戏，署名的成本就是一行字。**但必须做，否则就是侵权**。

## 四、为什么建筑和人物引不了（这是实测，不是猜）

我查了三家主流来源：

| 来源 | 星/规模 | 实际内容 | 能不能用 |
|---|---|---|---|
| OpenGameArt | 2009 年至今，3.5 万+ 材质 | Featured 全是 **Medieval / Dwarf / Isometric vehicles / Sci-fi** | ❌ 像素与西幻，混进来秒变拼盘 |
| Kenney | CC0 最干净 | **GitHub 上没有官方大仓**，全是三方零散镜像；导出以 PNG 卡通厚涂为主 | ❌ 风格完全不对 |
| game-icons | 4,313 个 | 单色图标，**没有场景插画** | ⚠️ 只能当图标，不能当房子 |

**我们现在的画风是「正面平视 + 纸墨线描 + 无透视」**——房子是一排屋顶剪影，人是火柴人。这个组合在开源素材里**基本不存在**，因为它不是任何主流品类（不是等距模拟经营，不是像素 RPG）。

**唯一可行的"引"法是描改**：拿 CC0 素材当参照，重新画成自己的 SVG 输出。CC0 允许改、允许商用、不用署名。但这条路的工作量**大于直接画**，只适合"我不知道该长什么样"的时候找参照。

## 五、真正的问题可能不是素材

说一句可能不太好听的判断：

> **你觉得画面不行，大概率不是"素材不够精美"，是"画面里没东西可看"。**

对比一下：
- 现在一座 Lv3 的房子 = 一个矩形 + 一个三角 + 一个小窗
- 玩家能看到的"信息"= 3 个形状

素材再精美，一个矩形还是矩形。让它"有东西可看"的是**附加物**：

| 加什么 | 成本 | 感知 |
|---|---|---|
| 屋檐加两道瓦纹 | 2 行代码 | 房子像房子了 |
| 窗里加灯晕（夜晚） | 1 个 `<circle>` + 透明度 | 有人住 |
| 屋顶加烟 | 已有 | 有人做饭 |
| 墙根加柴堆、晾衣绳 | 各 3 行 | 有人生活 |
| 雪天在屋顶留一道雪线 | 2 行 | 季节变了 |
| 门口一条被踩出来的土路 | 1 条 `path` | **人真的在走** |

**这 6 条加起来不到 40 行 SVG，全部零依赖、零 KB 增加、风格天然统一。**

比引 5MB 素材有效得多。

## 六、纸纹：不要引，用滤镜生成

纸墨风需要一个"纸的底子"。传统做法是引一张 200KB 的纸纹 PNG。

**不用。** SVG 有 `feTurbulence`：

```svg
<filter id="paper">
  <feTurbulence type="fractalNoise" baseFrequency="0.8" numOctaves="3"/>
  <feColorMatrix type="saturate" values="0"/>
  <feComponentTransfer><feFuncA type="linear" slope="0.04"/></feComponentTransfer>
</filter>
```

**零 KB，无限分辨率，手机上也不掉帧**（因为应用在一个静态层上，不需要每帧重绘）。

## 七、具体建议：图标引，场景自己画厚

| 动作 | 工作量 | 效果 |
|---|---|---|
| **引 9 个资源图标 + 4 个 UI 图标** | 半天 | 数字终于有形状了，占画面 8% 的那层从最弱变最强 |
| **建筑加 6 种附加物**（瓦纹/灯晕/柴堆/晾衣绳/雪线/土路） | 半天 | 房子"有人住" |
| **纸纹用滤镜** | 1 小时 | 整屏从"色块"变"纸" |
| 引开源场景素材 | — | **不做**（无匹配，会毁风格） |

前三条做完，画面信息密度大约翻 3 倍，体积只增加 26KB。

## 八、我不确定的三处

1. **图标染色后会不会太"图标"**：单色剪影放在纸墨场景里，可能显得像 App 而非游戏。要真跑一张图看。
2. **9 个图标够不够认**：木/石/肉/布/铁/钱/药/文化/治安，其中"文化"和"治安"很难用一张图说清。可能还是得配字。
3. **附加物加多了会乱**：18 个人 + 7 座房 + 6 种附加物，390px 宽一屏可能糊成一团。要按人口分档显示，人少时少画。

|---|---|---|
| 1 | 引 game-icons 做资源图标 | **引**，18KB，代价是一行署名 |

# 十、修正（13:50）：原结论作废，方向改掉

> 我上面的判断有一个根本性错误：**我把问题当成"画得好不好看"，你要的是"少动手"。**
> 这是两件事。以下结论替换前九节的建议。

## 10.1 错在哪

前面我论证的是"开源素材风格不匹配"。这个论证本身没错，但**它回答的是另一个问题**。

你的原话：**"有开源的素材的话尽量可以少自己动手"**——诉求是工时，不是画质。

所以正确的评估轴应该是：**用开源素材能省掉多少绘制工作，代价是什么。**

## 10.2 重新实测：4239 个图标里其实有东亚一整套

我用 git trees API 把 `game-icons/icons` 全部 4,239 个 SVG 路径拉下来逐个筛，找到的东西比我原来判断的多得多：

| 用途 | 图标 | 备注 |
|---|---|---|
| 木场 | `delapouite/axe-in-log` | 斧头劈在木头上 |
| 猎屋 | `delapouite/hut` | 茅屋 |
| 医馆 / 民居 | `delapouite/house` | |
| 私塾 | `delapouite/bookshelf` | |
| 铁匠铺 | `delapouite/blacksmith` | |
| 集市 | `delapouite/shop` | |
| 灯塔 | `delapouite/pagoda` | **宝塔**，东亚感很强 |
| 镇门 / 升阶 | `delapouite/medieval-gate`、`temple-gate` | |
| 祠堂 | `delapouite/shinto-shrine` | |
| 桥 | `delapouite/japanese-bridge` | |
| 整村（三档） | `delapouite/village` / `huts-village` / `caro-asercion/medieval-village-01` | 一张图当一个阶段 |
| 木 / 肉 / 布 / 钱 / 药 / 文化 / 治安 | `log` / `meat` / `clothes` / `coins-pile` / `medicines` / `tied-scroll` / `lantern` | **七个资源全部对上** |

**"七座建筑 + 九个资源"这套需求量，在开源里是齐的。**

我原来只搜了 house/castle/tower 就下结论，漏了 pagoda、shinto-shrine、temple-gate 这些东方题材——那是我的检索失误，不是素材不存在。

## 10.3 实测预览

`docs/material-preview.html`（同目录 `preview-shot.png` 是截图）——用真实图标渲染，没有一笔手绘。

看下来的结论：
- **建筑图标拼一排，观感是"木刻/印章插图"**，和纸墨风其实是同一族
- 宝塔、集市、书架、茅屋这四个特别对味
- 整村三张图可以直接当"阶段背景"，升阶时整张换
- 唯一出戏的是 `medieval-village-01`（教堂尖顶，偏欧洲），可以不用

## 10.4 工时账（[估算，未实测]）

| 部分 | 现在（手绘） | 换开源图标 |
|---|---|---|
| 7 座建筑 | 6 个函数 + 参数化，约 300 行 | 7 个 `<use>` + 一层染色，约 30 行 |
| 9 个资源图标 | 小圆点 + 文字 | 9 个 `<use>` |
| 场景背景 | 天空/地面/远山，约 80 行 | 保留（见 10.6） |
| **以后加新建筑** | **每次都要画** | **每次只需选一张图** |

省的不是这次，是**以后每一次**。这是这条路的真正价值。

体积：20 个图标内联后约 35KB，`index.html` 从 54KB 到 89KB，单文件 PWA 没问题。

## 10.5 图标没有等级，用"叠加"解决

图标最大的短板：Lv1 和 Lv5 长得一样。手绘可以画高、画宽、加二楼，图标不行。

**解法不是重画，是叠加小图标：**

| 等级 | 表现 |
|---|---|
| Lv1 | 建筑图标本身 |
| Lv2–3 | 旁边加 1 个小图标（如铁匠铺 + 锤子、集市 + 钱袋） |
| Lv4–5 | 加 2 个 + 一圈淡光晕（夜间暖色） |

**这套"等级语言"只用图标，不用画新图**，而且比"房子变大"更容易一眼读出来。

## 10.6 保留手绘的只有三处

这三处不画细节，只画**氛围色块**，代码量很小：

| 保留 | 为什么 |
|---|---|
| 天空渐变（昼夜/雨雪变色） | 图标是黑白剪影，没有天就没有时辰感 |
| 地面与路 | 需要一个"踩得住"的底 |
| 夜里的灯晕 | 暖光圈是"有人住"的唯一信号 |

**其余全部换成图标。**

## 10.7 新结论

| # | 问题 | 结论 |
|---|---|---|
| 1 | 建筑用开源图标 | ✅ **换**，7 座全换 |
| 2 | 资源图标用开源图标 | ✅ **换**，9 个全换 |
| 3 | 场景背景 | 保留手绘色块（不画细节） |
| 4 | 人物 | 保留火柴人（比图标人物更配场景，且已有） |
| 5 | 等级差异 | 叠加小图标，不重画 |
| 6 | 纸纹 | `feTurbulence` 滤镜，零 KB |

**这版的实现工作量：[估算] 半天到一天**，且之后每加一座建筑只需选图。
