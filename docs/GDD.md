## 1. 项目概述

### 1.1 一句话定位

把现实作息打卡转化为文本肉鸽冒险的资源引擎——**现实越自律，游戏世界越大**。

### 1.2 Fun Hypothesis

> 我相信——一个想改作息但反复失败的用户，在完成一个真实世界的作息任务后能**立刻**在游戏世界里看到一次确定的、不可逆的成长结算时，会感受到一种稀缺的确信感："我的坚持真的在改变什么"。
>
> 因为——这个设计把原本需要 3 个月才显现的自我改进结果，**压缩成了 3 秒内可感知的因果反馈**。拖延的本质不是懒惰，是因果链太长、看不见。

**验证信号**：D7 留存 ≥ 40%，D30 留存 ≥ 20%，连续打卡中位数 ≥ 5 天。`[PLACEHOLDER · 需实机验证]`

### 1.3 愉悦来源（Lazzaro 四把钥匙）

| 钥匙 | 在本项目中的角色 | 优先级 |
|---|---|---|
| Serious Fun（严肃乐趣） | 用户在改变真实自我，游戏是现实的镜子 | **主钥匙** |
| Easy Fun（简单乐趣） | 收集词条、探索事件、想知道下一段发生什么 | **副钥匙** |
| Hard Fun（挑战乐趣） | 连击维持与 run 内的资源管理 | 慎用，避免转化为压力 |
| People Fun（社交乐趣） | 无 | 本版本明确不做 |

**设计含义**：任何强化「Hard Fun」的功能（排行榜、限时挑战、竞争）都必须先证明它不会污染 Serious Fun 的主线。本版本的默认立场是：**不引入**。

### 1.4 反假设（这个设计可能怎么失败）

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 仪式疲劳 | 打卡动作在第 10-14 天变成新负担 | 设计支柱 02（零摩擦）；失败信号 A 类监控 |
| 数值脱敏 | 形态/选项变化不够快，动力衰减 | 设计支柱 05（能力扩张）；属性门槛前置解锁 |
| 自我放水 | 用户自欺欺人地打卡，游戏失去意义 | 不强制验证（保零摩擦），改用「附证据给加成」的正激励 |
| 情绪污染 | 现实工作任务进入游戏 → 游戏变压力源 | 支线任务三重准入 + 每周上限 3 条 |

### 1.5 Design Pillars（设计支柱）

| # | 支柱 | 含义 | 取舍规则 |
|---|---|---|---|
| 01 | **现实即棋盘** | 游戏内进度的唯一来源是现实行为 | 任何不依赖现实行动就能涨进度的机制，一律砍掉 |
| 02 | **零摩擦打卡** | 打卡必须在 3 秒内完成，一次点击 | 任何增加打卡步骤的功能，必须先证明能带来双倍留存才准进 |
| 03 | **即时结算** | 完成即刻看到数值跳动与反馈 | 任何"先攒着之后一起算"的设计都不合格 |
| 04 | **宽容优于惩罚** | 漏打卡不归零，恢复机制是核心而非补丁 | 任何造成"永久损失"的设计必须同时给出恢复路径 |
| 05 | **可感知的能力扩张** | 现实自律 → 游戏内选项与世界变大 | 如果坚持 30 天和坚持 3 天的可选项一样多，设计失败 |

> **支柱 05 修订记录**（v0.1）：原表述为「可感知的形态变化（角色变形）」。因本项目不采用人物形象，改为以「选项与世界扩张」为载体。修订理由：形象变化是装饰性奖励，选项扩张是**权力感**奖励，后者对长期留存的驱动力显著更强。

### 1.6 目标使用场景

| 时段 | 动作 | 说明 |
|---|---|---|
| 白天不定时 | 打卡（完成任一项现实任务即打） | 单项打卡，不要求一次打完 |
| 22:00 前后 | 戒断打卡、准点睡觉打卡 | 当日收尾 |
| 22:30-23:00 | **1 次肉鸽 run（3-5 分钟）** | 睡前主娱乐时段 |
| 任意碎片时间 | 查看属性面板、兑换清单 | 无强制 |

## 2. 核心循环

### 2.1 三层钩子

| 层级 | 时长 | 循环内容 | 钩子 |
|---|---|---|---|
| **Moment-to-moment** | 0-30 秒 | 读到一段文本 → 做一个选择 → 看到后果回显 | 「我的选择改变了什么」 |
| **Session loop** | 3-5 分钟 | 消耗精力进入 run → 推进 5-7 个节点 → 结算积分与词条 | 「这一局能挖到多深」 |
| **Long-term** | 数周 | 打卡累积属性 → 属性解锁全局内容 → 解锁新世界与事件 | 「现实里多自律一天，游戏里世界大一分」 |

**关键设计**：内循环的回环动力不是"我应该打卡"，而是"**我想看看它接下来变成什么样**"。好奇心牵引 > 责任感推动。

### 2.2 大循环（现实 ↔ 游戏）

```
现实打卡（主线+支线）
   ↓ 产出
精力（唯一入口资源）
   ↓ 消耗
肉鸽冒险（3-5 分钟 run）
   ↓ 结算
收获（积分 + 词条 + 属性点）
   ↓ 分流
├─ 属性点 → 永久成长 → 回流提升下次冒险（meta 回路）
└─ 积分  → 现实兑换 → 兑现实物奖励（终局出口）
```

**设计意图**：不让打卡直接兑换实物。中间强制插入一次「冒险」过程，使兑换行为带有随机性与故事性。这解决了"打卡换奶茶太单薄"的问题，同时创造出「拿去冒险」与「攒着兑换」之间的真实机会成本——**这是本设计新增的核心玩家决策**。

## 3. 经济系统

### 3.1 货币定义

| 货币 | 性质 | 上限 | 是否可消耗 | 作用域 |
|---|---|---|---|---|
| **精力** Energy | 日循环燃料 | 6 `[PLACEHOLDER]` | 是 | 进入肉鸽冒险 |
| **积分** Points | 兑换货币 | 无上限 | 是 | 现实兑换清单 |
| **词条** Traits | 能力修饰器 | 无上限 | 否（收集品） | run 内生效 |
| **属性** Attributes | 永久累积值 | 无上限 | 否（只累积） | 全局判定与解锁门槛 |

**设计说明**：属性不是货币，是「能力水位」。它不可被消耗、不可被交易——这是「现实即棋盘」支柱在数值层的体现：**时间投入不可逆，因此永久成长也不可逆**。

### 3.2 Sources（产出口）

| 来源 | 产出 | 频率 | Rationale |
|---|---|---|---|
| 主线打卡（完成 1 项） | +1 精力 / +1 积分 / +1 对应属性 | 每天，最多 7 次 | 1:1:1 是最容易心算的比率，避免用户为算账分心 |
| 满勤加成（7/7 全完成） | +1 精力 / +5 积分 | 每天 | 5 分 ≈ 日积分的 18%——够诱人，但不至于让断链变成毁灭性打击 |
| 连击系数 | 积分产出 ×1.0 ~ ×2.0 | 持续 | **只作用于积分**，硬约束 |
| run 结算 | +3 ~ +15 积分 / +0 ~ +2 词条 | 每次 run | 与推进节点数挂钩，见 5.5 |
| 支线任务完成 | +20 积分 / +1 稀有词条（每周前 3 条限定） | 每周 ≤ 5 次 | 稀缺源。单条积分由 +30 下调至 +20，防止支线收益盖过主线自律收益（支柱 01），见 4.2 |
| 精力溢出折算 | 溢出 2 精力 → 1 积分 | 每天自动 | 温和损失（支柱 04）：既有"该花掉"的提示，又不至于硬性惩罚 |
| 附证据加成 | 该项积分 ×1.5 | 打卡时可选 | 正激励替代强制验证，见 4.1.1 |

### 3.3 Sinks（消耗口）

| 出口 | 消耗 | 换得 | 限制 |
|---|---|---|---|
| 进入肉鸽 run | 3 精力 | 一次完整冒险 | 受精力约束，理论上每天最多 2 次 |
| 现实兑换 | 积分 | 实物奖励 / 特权 | 无限制 |
| 精力溢出 | 溢出的精力 | 折半转积分 | 被动触发 |

**平衡铁律**：每一个 source 必须能找到对应 sink。当前唯一无上限的 source 是**积分**，其对应 sink 是**现实兑换**。若兑换清单失去吸引力，积分将无限积累——这是本经济系统最需要监控的通胀点（见 3.5）。

### 3.4 关键数值与 Rationale

**精力上限 = 6** `[PLACEHOLDER]`

- 推导：1 次 run 消耗 3 精力 → 上限 6 = 每天最多 2 次 run，总时长 6-10 分钟。
- 假设：用户每日可支配娱乐时间约 10-20 分钟（睡前窗口）。若实测用户每日愿意投入 > 30 分钟，上限应上调至 9（3 次 run）。
- 上限存在的意义不只是防溢出，更是**制造紧迫感**：精力满了不花＝浪费，这构成「今天必须打卡」的推动力。

**积分日产出 ≈ 28 分** `[PLACEHOLDER]`

- 计算：打卡 7 项 = 7 分 + 满勤 5 分 + 2 次 run 平均 16 分 = 28 分。
- 用途：以「日产出 × 天数 ≈ 档位」反推兑换阶梯。

**连击系数**

| 连续满勤天数 | 积分倍率 | Rationale |
|---|---|---|
| 1-6 | ×1.0 | 基线 |
| 7-13 | ×1.2 | 第 7 天是历史失败点，此处给第一次跃迁，制造"跨过那个坎"的仪式感 |
| 14-20 | ×1.5 | |
| 21+ | ×2.0 | 封顶，避免无限膨胀 |

**硬约束**：连击系数**绝不影响精力产出**。若系数作用于精力，run 次数将随连击指数增长，游戏时长失控——这是明确标记的系统交互 bug 风险（见第 8 节）。

### 3.5 通胀风险与监控

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 积分只涨不花 | 积分余额 > 4 周产出量（≈ 800 分） | 说明兑换清单失效，需重新设计奖励诱惑力 |
| 精力长期溢出 | 溢出率 > 30% | 降低单次打卡精力产出，或提高上限 |
| 连击系数误作用于精力 | run 次数/天 > 3 | 硬约束，实现时以单元测试锁定 |
| 词条池枯竭 | 用户持有词条 < 5 且已 run > 20 次 | 词条池需扩充，见 5.3 |

## 4. 现实层：打卡与任务

### 4.1 主线任务

| # | 任务 | 提醒时间 | 频率 | 属性 | 积分 | 精力 |
|---|---|---|---|---|---|---|
| 1 | 按时起床 | 起床点 | 每天 | 志 +1 | +1 | +1 |
| 2 | 出去锻炼 | 19:00 | 工作日 | 身 +1 | +1 | +1 |
| 3 | 去洗澡 | 20:30 | 每天 | 身 +1 | +1 | +1 |
| 4 | 学习知识 | 21:00 | 每天 | 智 +1 | +1 | +1 |
| 5 | 戒断打卡 | 22:00 | 每天 | 志 +1 | +1 | +1 |
| 6 | 看娱乐书籍 | 22:30 | 每天 | 智 +1 | +1 | +1 |
| 7 | 准点睡觉 | 睡觉点 | 每天 | 身 +1 | +1 | +1 |

**属性日增速率**：工作日 身+3 / 智+2 / 志+2；周末 身+2 / 智+2 / 志+2

**时间安排的 rationale**：原清单中「戒断 22:00」与「看娱乐书籍 22:00」撞车（一条要抑制、一条要放松，互相拆台）。本版本将看娱乐书籍后移至 **22:30**，并把「洗脸洗澡」前置到 20:30，使晚间序列形成 锻炼 → 洗澡 → 学习 → 戒断 → 看书 → 睡觉 的单向流，无重叠。

**交互要求**：
- 打卡必须**一次点击**完成，无二次确认弹窗（支柱 02）
- 打卡后立即播放结算反馈（数值跳动 + 简短文案），时长 ≥ 1.2 秒 ≤ 2.5 秒
- 打卡时间不强制校验（不做"必须 22:00 整点打卡否则无效"的限制）

#### 4.1.1 附证据加成（可选机制）

| 项 | 设计 |
|---|---|
| 目的 | 在不破坏零摩擦的前提下，缓解「自我放水」风险（见 1.4） |
| 触发 | 打卡时长按可附一张照片 |
| 效果 | 该项积分 ×1.5 |
| 边界 | **不附照片不产生任何负面后果**。绝不做"未上传证据则打卡无效" |
| Rationale | 用正激励引导诚实，而非用强制验证制造摩擦 |

### 4.2 支线任务

**定义**：现实中由他人（家人、同学、同事）交付给你的一次性任务。

**三重准入（必须全部满足）**：

| # | 条件 | 合格 | 不合格 |
|---|---|---|---|
| 1 | 有明确完成标志 | 「提交那份报告」 | 「跟进那个项目」 |
| 2 | 投入可控、有终点 | 「帮妈妈修电脑」 | 「日常对接客户」 |
| 3 | 本人自愿承接 | 你主动答应的 | 被临时指派的 |

**硬性上限：每周最多录入 5 条。**（v0.2 由 3 条上调）

**设计意图**：这条上限是整个系统里最重要的一道保护。工作任务的完成标准由他人制定、难度不可控、随时可能变更。若全量接进游戏，将产生：

```
工作不顺 → 游戏卡关 → 游戏变成压力源 → 弃坑
```

这正是本游戏要解决的原问题的反面。**游戏必须保护自己不被现实的工作流吞没。**

**一旦上限提到 5 条，一周里几乎每天都有支线，距离「任务管理器」只差一步——因此准入必须执行得更严，而不是更松。**

**奖励**

| 项 | 规则 | Rationale |
|---|---|---|
| 积分 | **+20 / 条** | v0.2 由 +30 下调。5 条 × 30 = 150 分 ≈ 周档位（150），会让「别人给的任务」收益盖过你自己的自律收益，违反支柱 01 |
| 稀有词条 | **每周前 3 条各给 1 个** | 词条是稀缺资源，限量才能保值。第 4-5 条只给积分，不给词条 |
| 每周上限 | 5 条 | 见上 |

`[PLACEHOLDER · 支线收益占周总积分比例建议控制在 35% 以内，需实机统计]`

### 4.2.1 录入强制字段（v0.2 新增）

每条支线录入时**必须**填写「完成标志」字段——一句可判定的描述。

| 项 | 内容 |
|---|---|
| 字段名 | 完成标志 |
| 类型 | 单行文本，必填，不可跳过 |
| 合格示例 | 「把电脑修好并能正常开机」 |
| 不合格示例 | 「跟进一下」「尽量搞定」 |
| 校验方式 | 仅做必填 + 最小长度校验（少于 6 字时二次提醒） |
| 设计意图 | 把准入门槛从「用户自行判断」变成「系统强制」。**填不出完成标志，等价于这条任务不该进游戏。** |
| 边界 | **不做语义校验**。用 AI 判断"这个任务是否够明确"会引入不确定性与额外成本，得不偿失 |

### 4.3 断链保护机制

**免死金牌**

| 项 | 规则 | Rationale |
|---|---|---|
| 获取 | 每连续 7 天全勤赠 1 张 | 与连击系数跃迁节点同步，形成"满 7 天双重奖励"的节奏 |
| 持有上限 | 3 张 `[PLACEHOLDER]` | 允许 3 次失误，但不允许长期躺平 |
| 使用 | 漏打当天自动消耗 1 张，连击不清零 | 全自动，无需用户操作（支柱 02） |
| 代价 | 当日无满勤加成 | 有成本，避免免死金牌变成"合法的偷懒券" |

**失败状态定义**：

| 状态 | 条件 | 处理 |
|---|---|---|
| 断链 | 漏打且无免死金牌 | 连击归零，**已积累的属性与积分不清零** |
| 关键约束 | — | 任何情况下**不得清零属性、积分、词条**——这是支柱 04 的红线 |

## 5. 游戏层：肉鸽冒险

### 5.1 单局结构（3-5 分钟）

| 阶段 | 时长 | 内容 | 玩家决策 |
|---|---|---|---|
| 进入 | ~5 秒 | 消耗 3 精力，选择本次「入口」 | 选哪个入口（影响事件池权重） |
| 推进 | 5-7 节点 × 30-40 秒 | 逐节点阅读文本、做选择 | 每个节点 1 次选择 |
| 结算 | ~10 秒 | 展示积分、词条、属性变化 | 无 |

**节点类型分布**（5-7 节点的一次 run）`[PLACEHOLDER]`

| 类型 | 占比 | 说明 | 是否必出 |
|---|---|---|---|
| 遭遇 | 55% | 常规异闻事件，2-3 个选项 | — |
| 抉择 | 20% | 二选一，两个选项都有明确代价 | — |
| 词条 | 15% | 直接获得一个临时词条 | — |
| 锚点 | 10% | 关键事件，触发定力判定 | 第 5 节点必出 1 次 |

### 5.2 run 内资源：定力

| 项 | 规则 | Rationale |
|---|---|---|
| 初始值 | `8 + floor(志 / 10)`，上限 20 `[PLACEHOLDER]` | 让「志」属性有直接的 run 内反馈——现实里不戒断、不早起，游戏里就更容易崩 |
| 扣除 | 越级失败扣 4；普通失败扣 2 | |
| 归零 | run 立即结束，进入结算 | 肉鸽的失败是正常分支，不是惩罚 |

**为什么用「定力」而不是「血量」**：血量暗示肉体伤害，与都市异闻的基调不符；定力把 run 内的失败解释为"心志动摇"，与现实层的「志」属性语义连贯。

### 5.3 判定规则（确定性优先）

| 情形 | 判定 | 设计理由 |
|---|---|---|
| 选项门槛 ≤ 当前属性 | **必定成功** | 努力必须有确定回报。随机失败会让用户觉得"我自律白费了"，直接摧毁 Serious Fun |
| 选项门槛 > 当前属性（越级尝试） | 成功率 = 属性值 / 门槛；失败扣双倍定力 | 越级是玩家自愿冒的险，赌输不冤 |

**红线圈定**：**不得在门槛内的事件上引入随机失败**。这是「现实即棋盘」支柱的底线——如果自律换来的仍然是掷骰子，整个因果链就断了。

### 5.4 词条系统

| 类型 | 存续 | 来源 | 数量上限 |
|---|---|---|---|
| 临时词条 | 单次 run 内有效，局末消失 | run 内「词条」节点 | 无（受 run 长度约束） |
| 永久词条 | 永久保留 | 支线任务 / 深层通关 / 里程碑奖励 | 无 |

**词条示例**（第一版池 `[PLACEHOLDER · 建议 24 个]`）

| 词条 | 类型 | 效果 | 设计意图 |
|---|---|---|---|
| 夜视 | 临时 | 含「黑暗」标签的事件判定 +2 | 制造 run 内的构筑方向 |
| 旧识 | 临时 | 遇「故人」标签事件时多一个选项 | 提高选项密度 |
| 冷静 | 临时 | 每次失败少扣 1 定力 | 容错型构筑 |
| 执念 | 临时 | 每通过 1 节点 +1 积分，初始定力 -2 | 贪婪型构筑（风险换收益） |
| 晨型人 | 永久 | 所有「白天」事件判定 +1 | 长期成长的可见回报 |
| 手账 | 永久 | run 结算积分 +10% | 复利型 |

**构筑张力设计**：临时词条中必须同时存在「加收益」与「减风险」两类，且部分词条自带代价（如「执念」），迫使玩家在 run 内做路线取舍。**如果所有词条都是纯增益，run 内将不存在决策，肉鸽就退化成读文本。**

### 5.5 结算规则

| 结果 | 积分 | 词条保留 |
|---|---|---|
| 失败（定力归零） | 已通过节点数 × 2 | 临时词条全部清空 |
| 通关（走完 5 节点） | 节点数 × 2 + 10 | 同上 |
| 深层通关（走完 7 节点） | 节点数 × 2 + 20 | 同上，且 10% 概率掉落 1 个永久词条 |

**失败不惩罚已有资产**：失败只损失本次 run 的潜在收益，不清空任何已积累资源（支柱 04）。

### 5.6 内容生产方案（成本控制）

**问题**：文本内容量是这类游戏最大的持续成本。30 个手写事件撑不过一周就会重复。

**方案**：骨架 + 组合

```json
{
  "id": "ev_night_004",
  "tags": ["night", "street", "dark"],
  "weight": 10,
  "text": "路灯下，一个穿旧棉袄的老人在翻垃圾桶。他抬头看了你一眼，眼神异常清澈。",
  "options": [
    { "text": "上前搭话", "req": { "zhi": 5 }, "outcome": "..." },
    { "text": "绕开", "req": {}, "cost": 1, "outcome": "..." }
  ]
}
```

**三个复用杠杆**：
1. **标签加权抽取**——入口决定 tags 权重，同一批事件在不同入口下组合出不同序列
2. **状态变量改写文本**——`{定力}` `{属性}` 等变量注入，同一骨架在不同状态下文本不同
3. **词条改写判定**——同一事件在持有不同词条时，可用选项不同

**第一版内容量**：30 个手写骨架事件 + 24 个词条 = 足以跑通核心循环 `[PLACEHOLDER]`

## 6. 成长系统

### 6.1 三属性

| 属性 | 来源任务 | run 内作用 | 全局作用 |
|---|---|---|---|
| **身** | 出去锻炼、去洗澡、准点睡觉 | 「体力类」选项门槛 | 解锁远行、荒野类世界 |
| **智** | 学习知识、看娱乐书籍 | 「知识类」选项门槛 | 解锁书斋、古籍、档案馆 |
| **志** | 按时起床、戒断打卡 | 决定初始定力 | 解锁独处、绝境、长夜 |

**三属性的语义分工 rationale**：不是按任务类别机械切分，而是按「现实行为 → 游戏能力」的隐喻映射——身体的自律对应行动力，认知的投入对应洞察力，意志的坚持对应抗压力。

### 6.2 全局解锁表（支柱 05 的落地点）

| 属性 | 门槛 | 解锁内容 | 达成天数估算 |
|---|---|---|---|
| 身 | 20 | 「夜跑」类事件 | 约 7 天 |
| 身 | 45 | **远行世界**（第 2 张地图） | 约 16 天 |
| 身 | 90 | **荒野世界**（第 3 张地图） | 约 32 天 |
| 智 | 15 | 「书斋」类事件 | 约 8 天 |
| 智 | 35 | 「古籍」事件链 | 约 18 天 |
| 智 | 70 | **档案馆世界** | 约 35 天 |
| 志 | 15 | 「独处」类选项 | 约 8 天 |
| 志 | 35 | 「绝境」选项（高风险高回报） | 约 18 天 |
| 志 | 70 | **长夜世界** | 约 35 天 |

`[PLACEHOLDER · 天数按满勤速率推算，实际需按真实完成率下调门槛]`

**解锁节奏 rationale**：第一个解锁点设在 **7-8 天**——这是历史失败点（上次坚持了 1 周就断）。在用户最可能放弃的位置，必须给他一个"新东西出现了"的正反馈。这是本表最重要的一条设计。

### 6.3 属性与 run 难度的关系

属性越高 → 可选选项越多 → 推进越深 → 结算收益越高。

**这条链路必须闭合**。如果属性只涨但不影响 run 体验，用户会在 2 周内识别出"这只是个数字"，然后弃坑（失败信号 B 类）。

### 7.2 设计约束

| # | 约束 | 理由 |
|---|---|---|
| 1 | 即时档必须**当天可达** | 如果第一档要攒 3 天，奖励的即时性就失效了 |
| 2 | 清单内容**由用户本人填写** | 别人指定的奖励，大脑不认账 |
| 3 | 必须是**24 小时内能买到**的东西 | 保持"即时兑现"的体感 |
| 4 | **不得是伪装成奖励的任务** | 「买一本 CPA 教材」是任务，不是奖励。这条约束防止用户自己骗自己 |
| 5 | 积分是钱包，**消费不清零** | 花多少扣多少，避免"攒月奖励期间不能享受任何小奖励"的苦行 |

## 附录 A：AI 接入方案（v0.2 新增 · 待决策）

### A.1 权限边界（不可协商）

| 环节 | 归属 | 说明 |
|---|---|---|
| 抽取骨架事件 | 代码 | |
| **判定选项门槛** | **代码** | AI 无权介入 |
| **定力扣除** | **代码** | AI 无权介入 |
| **积分结算** | **代码** | AI 无权介入 |
| 文本渲染 | AI | 唯一授权给 AI 的环节 |
| 氛围与语气 | AI | |
| 变量注入后的措辞 | AI | |

**红线**：AI 不得产出任何影响游戏状态的数值。理由见 A.2。

### A.2 不把判定交给 AI 的三条理由

| # | 风险 | 后果 |
|---|---|---|
| 1 | LLM 无法稳定输出结构化门槛 | 同一选项时成时败，摧毁「现实即棋盘」的因果感 |
| 2 | 单次调用延迟 3-8 秒 | 5 节点累计多等半分钟，违反支柱 03，3-5 分钟的单局被拉长一倍 |
| 3 | 强依赖网络 | 出差 / 弱网环境下不可用 |

### A.3 分阶段接入

| 阶段 | 内容 | 前置条件 |
|---|---|---|
| Phase 1 | 纯骨架，零 AI | 无。**必须先验证骨架版循环成立** |
| Phase 2 | AI 渲染（结构不变，只换文字） | Phase 1 通过 14 天观察窗 |
| Phase 3 | AI 参与事件权重、生成新骨架 | Phase 2 稳定运行 |

**判断依据**：AI 解决的是「内容会不会腻」，Phase 1 验证的是「循环成不成立」。两件事必须分开验——**如果骨架版本本身就不好玩，AI 只会更快地生产出无聊内容。**

### A.4 工程要点

| 项 | 方案 |
|---|---|
| 接口 | OpenAI 兼容格式；key 存本地，由用户自填 |
| 预生成 | 进入 run 时并发预生成全部节点文本，规避逐节点等待 |
| 降级 | AI 超时 3 秒 → 直接使用骨架原文，不打断节奏 |
| 缓存 | 以「骨架 ID + 状态指纹」为缓存键，减少重复调用 |
| 隐私 | 打卡数据外发默认**关闭**，需用户显式开启 |

### A.5 AI 的差异化价值（不是成本优化）

接入 AI 的核心理由不是省内容成本，而是**叙事映射**——让事件呼应当日真实状态：

| 当日现实状态 | 文本层表现 |
|---|---|
| 完成锻炼 | 出现与身体疲劳、夜路相关的意象 |
| 漏打戒断 | 事件倾向「心志动摇」分支 |
| 连续 7 天满勤 | 叙述中出现「变化」的暗示 |

手写骨架做不到这一点。这是把支柱 01 从**数值映射**推进到**叙事映射**的唯一路径。
