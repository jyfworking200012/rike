# 《小镇》v4 设计文档

> 一句话：**你早上做的七件小事，变成七个人；七个人撑起一座镇。**

---

## 一、Fun Hypothesis

**这游戏好玩的核心是：我每天不愿做的那几件小事，是小镇里某个人一整天的活。我不做，他就来不了；他来了，镇子才长得出下一块砖。**

不是"打卡换积分"，是"打卡 = 招人 = 有人替我干活 = 镇子变大"。

---

## 二、Design Pillars（不可妥协）

| # | 支柱 | 判据（怎么算违反） |
|---|---|---|
| P1 | **每份资源都能追到人** | 任何产出必须写明"谁干的"，出现"系统赠送"即违反 |
| P2 | **镇子每天必须看得见变化** | 打开若画面与前次完全相同，即违反（新建筑/新灯/新人/新路） |
| P3 | **繁荣本身是压力** | 人口涨而麻烦不涨，即违反。人越多，事件越频繁越狠 |
| P4 | **断档只停滞，不倒退** | 任何"清零/烧毁/人口归零"即违反。最坏结果是"今天没长" |

---

## 三、因果链（这是上一版缺的东西，逐环可追）

```
早起 ──→ 老陈(樵夫) ──→ 木
                          ↓
                    ┌─────┴─────┐
                    ↓           ↓
                 木棚(住处)   陷阱
                    ↓           ↓
              容量↑ 收人      阿岩(猎人)产出↑
                    ↓           ↓
              更多人           肉
                    ↓           ↓
        石匠/铁匠/账房/守夜人   喂饱全镇
                    ↓
              石·铁·钱·治安
                    ↓
        井 / 粮仓 / 铁匠铺 / 集市 / 瞭望塔 / 祠堂
                    ↓
              能扛住更大的事件
```

**闭环点**：容量卡住 → 人来了住不下 → 必须建木棚 → 建木棚要木 → 要木得有人砍 → 要人得打卡。

任何一环断开，链条就停在那，玩家能立刻看见停在哪一环。**这就是"看得懂"的定义。**

---

## 四、核心循环

| 层 | 时长 | 内容 |
|---|---|---|
| Moment | 0–5 秒 | 点一个打卡项 → 一个村民的名字出现 → 镇口多一个人影 |
| Session | 3–5 分钟 | 打卡 → 过夜（产出结算）→ 一个事件 → 可能建一栋 |
| Long-term | 2–6 周 | 破屋 → 木棚群 → 石屋 → 有井有塔有祠堂的镇子 |

---

## 五、数值表

### 5.1 七件事 → 七个人（每人每天产出）

| 打卡 | 村民 | 职业 | 基础产出 | 需要建筑 |
|---|---|---|---|---|
| 早起 | 老陈 | 樵夫 | 木 +4 | — |
| 运动 | 阿岩 | 猎人 | 肉 +2 | — |
| 洗澡 | 苏姐 | 洗衣妇 | 布 +1 | — |
| 学习 | 白先生 | 石匠 | 石 +2 | — |
| 不刷手机 | 锤子 | 铁匠 | 铁 +1 | 铁匠铺 |
| 阅读 | 纸生 | 账房 | 钱 +2 | 集市 |
| 早睡 | 灯 | 守夜人 | 治安 +1 | — |

> **rationale**：木 +4 使「木棚 10 木」= 2.5 天，即"连续三天早起能盖第一间房"。这是第一周唯一必须记住的数字。

### 5.2 消耗

| 项 | 值 | rationale |
|---|---|---|
| 每人每天吃 | 0.5 肉（累计取整） | 人口 6 时 = 3 肉/天 = 猎人(2)+陷阱(1)，刚好打平。逼玩家在"再招人"和"加陷阱"之间选 |
| 人口容量 | 破屋 1 + 木棚 2/间 + 石屋 4/间 | 容量是唯一硬闸，制造"打卡了但住不下"的痛感 |
| 住不下的人 | 留 1 木后离开 | 不让玩家觉得白干，同时提示"该盖房了" |

### 5.3 建筑（成本均为 [PLACEHOLDER·首轮 playtest 后调整]）

| 建筑 | 木 | 石 | 铁 | 钱 | 布 | 效果 |
|---|---:|---:|---:|---:|---:|---|
| 木棚 | 10 | | | | | 容量 +2 |
| 石屋 | 20 | 15 | | | | 容量 +4，防火 |
| 陷阱 | 5 | | | | 2 | 猎人的肉 +1 |
| 粮仓 | 15 | 6 | | | | 食物消耗 ×0.6 |
| 井 | | 10 | | | | 免疫旱灾/疫病 |
| 铁匠铺 | 15 | 12 | | | | 解锁铁 |
| 集市 | 20 | | 8 | | | 解锁钱，可买肉 |
| 瞭望塔 | 18 | 16 | | | | 事件提前一天预警 |
| 祠堂 | 30 | 30 | 12 | 20 | | 事件概率 −40% |

### 5.4 事件

- **触发概率**：`0.35 + 人口 × 0.04`（上限 0.85）
- **强度档**：人口 ≥ 6 才可能出现"大事件"
- **每个事件 2–3 个选项，代价写在按钮上**，不允许"免费最优解"

已实现 12 个：野兽、暴雨、流民、行商、疫病、夜盗、干旱、塌方、喜事、征兵、迷路的旅人、冬天的第一场雪。

## 六、失败信号（Playtest 前先定义"坏掉长什么样"）

| 信号 | 表现 | 判定 |
|---|---|---|
| A. 看不懂 | 玩家问"木头哪来的""为什么人没留下" | 因果文案失败，P1 违反 |
| B. 看着没劲 | 玩家连续 3 天不看小镇画面 | 视觉反馈失败，P2 违反 |
| C. 算不过来 | 玩家说"太复杂了不想算" | 数值层数过多，需砍到 4 种资源 |
| D. 打卡绑架 | 玩家为游戏而做不想做的事，产生抵触 | 伦理红线，需加"可以少做"的正面反馈 |

## 七、与前三版的关系

| | v1 代币 | v2 院子 | v3 夜行 | **v4 小镇** |
|---|---|---|---|---|
| 打卡的作用 | 抽卡筹码 | 长一寸 | 夜行燃料 | **招人** |
| 资源因果 | 无 | 无 | 弱 | **人→产出→建筑→容量→更多人** |
| 可见变化 | 数字 | 静态院子 | 无 | **建筑逐栋长出、灯逐盏亮** |
| 突发事件 | 随机事件（无后果） | 无 | 有 | **有，且强度随繁荣上升** |
| 断档后果 | 清零 | 停滞 | 停滞 | 停滞（人离开，房子还在） |
