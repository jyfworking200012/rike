# 《日课》开源生态调研

> 调研日期：2026-10-08
> 目的：找出可对标的同类项目、可复用的内容引擎、可零成本使用的素材与工程组件
> 方法：网络检索 + 仓库页面实读。**所有结论仅基于检索到的一手描述，未经本地跑通验证**

---

## 0. 结论速览

**三个判断，按重要程度排序：**

**① 有直接对标项目，而且不止一个。** `hakai-protocol-v2` 与 `the-forge` 两个项目的机制清单，和《日课》GDD 的重合度在 70% 以上——包括你最在意的「连击断裂保护」。它们是**已上线验证过**的，可以省掉大量试错。

**② 但「文字肉鸽 run」这一层，是空白。** 所有对标项目的结构都是 `打卡 → 直接给 XP/属性`，中间没有一层。而《日课》的核心创新恰恰是 `打卡 → 精力 → 一局冒险 → 积分`。**这一层没人做过，它是差异化所在，只能自研。**

**③ 内容成本有现成解法。** Tracery（文本语法扩展）能直接解决「30-50 个骨架事件撑不过一周」的问题，且是 Apache 2.0 协议，可自由商用。

**⚠️ 一个立刻要注意的风险**：中文开源字体（霞鹜文楷等）完整版单字重约 **25MB**。塞进手机 PWA 会直接毁掉首屏加载体验。要用必须上 Lite 版或子集化。

## 1. 直接对标项目

### 1.1 Habitica —— 行业标杆，也是最好的反面教材

| 项 | 内容 |
|---|---|
| 仓库 | `github.com/HabitRPG/habitica` |
| 规模 | 约 14.1K stars / 4.4K forks / 26,000+ commits |
| 技术栈 | Node + Express + MongoDB，前后端分离，有独立 Android / iOS 仓库 |
| 协议 | **代码 GPL v3**；**美术资产 CC-BY-NC-SA 3.0（禁止商用）** |
| 状态 | 2012 年至今。**2026-08-04 起暂停接受社区 PR**（官方称「技术环境与交互方式变化」）。README 明确**禁止提交 AI 生成的代码** |

**它是怎么做的**：打卡 → 得 XP / Gold → 角色升级、买装备、养宠物、打公会 boss。失败扣 HP，HP 归零掉装备。社交是它的核心（公会、挑战、组队）。

**它对《日课》的价值在于三件事**：

1. **机制天花板参考**——它把「打卡→RPG」这条链做得最完整，可以看清这条路能走多远
2. **验证了社交是强需求**，但也验证了**你不是它的用户**：你要单机私密，它靠公会留存
3. **它是失败案例的样本**：14 年、1400 万用户量级，但「坚持不下去」依然是最普遍的抱怨。说明**光有 XP 和装备不够**——这恰好印证了 GDD 里「即时因果反馈」才是关键，而 Habitica 的反馈链太长（打卡 → 攒金币 → 买装备，跨天甚至跨周）

**可抄的**：等级曲线的数值手感、属性分类方式
**不能抄的**：美术资产（NC 协议）、代码（GPL 传染性）

### 1.2 ⭐ hakai-protocol-v2 —— 机制上最接近的实现

| 项 | 内容 |
|---|---|
| 仓库 | `github.com/Jeevan-0508/hakai-protocol-v2` |
| 形态 | **vanilla HTML/CSS/JS，零依赖、零构建、无需后端**，可装 PWA、离线可用 |
| 技术栈 | 4 个 JS 文件由 `index.html` 顺序加载：`engine.js`（约 2000 行，状态机+渲染）、`audio_engine.js`、`systems.js`、`dev_panel.js` |
| 存储 | localStorage |
| 部署 | GitHub Pages 静态托管；另打包了 Windows exe 与 PWABuilder 的 APK |
| 更新时间 | 最后提交 2026-09-13 |
| 协议 | 仓库有 LICENSE 文件（README 提到修正过授权人名），**具体条款需在仓库确认** |

**它最值钱的部分是 v2.3 的「留存系统」（Retention Systems）——几乎每一条都对应《日课》GDD 的某个设计：**

| hakai 的机制 | 具体做法 | 对应《日课》的哪条 |
|---|---|---|
| **Streak Shields** | 每满 7 天得 1 个盾，**最多存 3 个**；漏一天时下次开 App 自动消耗盾吸收，连续记录不清零 | **免死金牌**——完全撞车，可直接对标 |
| **Rebuild Protocol** | 真漏 2 天以上 → 接下来 3 天 **XP +50%**。被盾吸收的日子不算「漏」 | 治「断了就全废」的心理，GDD 里**没有这条，建议补** |
| **Daily Directive** | 每天 1 个轮换目标（清空全部 / 任意 3 个 / 9 点前完成第一个…），**按日期确定性抽取，刷新页面无法重掷**；时间窗过了就从池里剔除 | 对应「每日变化」，且解决了「刷新重掷」这个作弊漏洞 |
| **Shadow Caches** | 每个新完成的任务 **14% 概率掉箱**，分 Common/Rare/Epic。**每个任务每天只 roll 一次，取消再勾不能刷** | 对应 GDD 的随机暴击；**「防刷」这个细节 GDD 没写，很关键** |
| **Proximity Scan** | 显示**离你最近的 3 个解锁项及确切距离**（下一级、下一称号、下个生物、下个武器档、下个 boss） | GDD 有「属性解锁门槛」，但没写「距离可视化」。**这条强烈建议抄**——让人看见「还差 3 天」比什么都刺激 |
| **App Badge** | 安装后的 PWA 在桌面图标上显示剩余任务数（无推送服务器时唯一的提醒手段） | GDD 现在把提醒甩给系统日历。**这条更优雅，建议抄** |

**它的工程做法也值得学**：

- v2.3 的所有新系统写在**独立的 `systems.js`** 里，用**包裹（wrap）**方式挂到原引擎函数上，**不改原文件**；每个钩子都有 try 保护，**系统抛错就回退到原始行为，而不是白屏**。这是非常成熟的增量改造手法——正好治我们踩过的「改一处崩全局」。
- 新状态全部命名空间化到 `S.sys` 一个键，带默认值回填，**老存档静默迁移**。
- 每日本记账数据 **10 天后自动清理**，防 localStorage 膨胀。
- README 里写明了**在 headless Chrome 上跑了 64 条断言**（连续天数一致性、盾的发放/消耗/上限、跨日幂等、40 天缺席、宝箱防刷、九个 tab 渲染、25 次重复渲染幂等性）。

> ⚠️ 它踩过一个很典型的坑，值得记下来：`getHabitStreak` 把日期键按**本地午夜**解析、却用 `toISOString()` 格式化回字符串，导致 UTC 以东时区**「今天完成了但连续天数是 0」**。它的解法是把计分日界统一为 UTC。**我们在实现连击时必然会遇到同一个坑。**

### 1.3 ⭐ the-forge —— 产品哲学最好，直接对着「第二周放弃」开火

| 项 | 内容 |
|---|---|
| 仓库 | `github.com/ycianno/the-forge` |
| 协议 | **MIT**（最宽松，可自由改） |
| 技术栈 | 前端 vanilla（无框架无构建）+ Node/Express + SQLite（better-sqlite3）+ Docker |
| 其他 | 可装 PWA、支持推送、可选接本地 Ollama 做 Discord 代理 |
| 状态 | 极活跃，最后提交 2026-10-07，164 commits |

**它的 README 里有一句值得抄下来的话**：

> *"It tries hard not to be another app you abandon in week two."*
> （它努力不成为又一个你第二周就放弃的应用）

**它为此做的四个具体设计，每一条都值得《日课》直接借鉴：**

1. **打开即「今天」，什么都没有**（"It opens on Today and nothing else"）——把认知负担压到零。这比「功能丰富」重要得多。
2. **起步计划是每天 5 个任务，不是 15 个**（"a starter plan is five tasks a day, not fifteen — a day you can actually clear"）——**新用户的默认值必须是他能清空的**。《日课》现在一上来 7 项，建议第一周只默认开 5 项。
3. **用时间计量，不用勾选框计量**——「剩 3 项 · 1 小时 10 分」，而不是「剩 3 项」。原话是：*「分钟数让你在晚上 9 点能做出决定，而一堆方框只会让你觉得自己很糟」*。**这是个很锐利的洞察**：把「我今天又没做完」变成「我还有 40 分钟能做完」。
4. **每次打卡可撤销（undo）**——降低误操作成本。

**它还有两个机制可以对照**：

- 5 个属性（Discipline / Body / Mind / Vitality / Craft），**全部从已完成的打卡派生，不用手动录**——和《日课》的 身/智/志 同构
- **每周 Boss**：Boss 有 HP，**吃它的「弱点属性」伤害翻倍**。这个把「属性成长」变成了有目标的战斗，比单纯看数字强
- **Streak freeze**：可配置的宽限日，"so one bad day doesn't reset everything"

### 1.4 LifeUp —— 机制清单最全，且是中文开发者做的

| 项 | 内容 |
|---|---|
| 仓库 | `github.com/Ayagikei/LifeUp` |
| 形态 | Android App（另有 iOS 版 ulives）。**该仓库主要用于收集 issue 与发布试用版，不是完整源码仓库** |
| 生态 | 有 SDK、LifeUp Cloud、桌面端、文档站；**社区已有人做了 `lifeup-mcp`（MCP server，让 LLM 通过 SDK 操作 LifeUp）** |
| 中文支持 | 原生中文，翻译走 Crowdin |

**它的机制覆盖度是本文中最全的**：属性/技能（可自定义，不限于内置的力智敏）、商店（把奖励抽象成商品）、成就、番茄钟、**自定义抽奖箱（loot boxes）**、合成（crafting）。

**对《日课》最有参考价值的是两点**：

1. **「奖励抽象成商店商品」**——它把「看一场电影 / 休息 30 分钟 / 随机金币」都变成可购买的商品。这正是 GDD 里「现实兑换清单」的成熟做法，可以参考它的商品分类方式。
2. **`lifeup-mcp` 的存在证明了「外部程序读写习惯数据」是可行的**。这对应 GDD 附录 A 里 AI 读取打卡状态的方案——别人已经跑通了同一条路。

**但注意**：它的核心价值是「机制清单」，不是可复用的代码。想抄机制可以，想抄代码不行。

## 2. 叙事 / 内容引擎

这一层解决的是 GDD 里「**文字肉鸽最大的成本不是代码，是内容量**」的问题。

### 2.1 ⭐ Tracery —— 直接解决「骨架事件撑不过一周」

| 项 | 内容 |
|---|---|
| 仓库 | `github.com/galaxykate/tracery`（作者 Kate Compton，2013 年起） |
| 语言 | JavaScript（另有 Python / Lua / 等社区移植版） |
| 协议 | **Apache 2.0** |
| 依赖 | 零依赖 |

**它做什么**：给一份「语法」——把符号名映射到候选句子数组——它递归随机展开，生成完整文本。

```js
const rules = {
  origin: "#地点#里，#动作#。",
  地点:   ["走廊尽头", "值班室的窗边", "那截没灯的楼梯"],
  动作:   ["有东西在等你", "没人", "风把门吹上了"]
};
// 展开结果："走廊尽头里，风把门吹上了。"
```

**为什么它正好命中《日课》的需求**：

- GDD 里写的「事件写骨架 + 随机词条注入 + 状态变量改写文本」，**本质就是一套语法展开系统**。Tracery 已经把这个轮子造好了。
- **支持确定性随机**——`tracery.setRng(myRng)` 可以换成带种子的随机数源。这意味着**同一局 run 里的事件序列可以被种子复现**，调试和「分享你的这局」都变得可能。这是 GDD 没考虑到但很有价值的能力。
- Apache 2.0，自用商用都无约束。
- 上手成本极低——半天就能吃透。

**局限（必须说清）**：
- 它是**文本生成**，不是**逻辑引擎**。它不能做判定，不能改状态。
- 用法上必须严格分层：**Tracery 只负责渲染文本，门槛判定、数值结算依然由我们自己的代码管**。这和 GDD 附录 A「把 AI 关在文本层里」是同一条红线，只是把 AI 换成了 Tracery。
- 它是浏览器脚本，`file://` 协议下用 `<script>` 标签直接引没问题，但**如果要外挂 json 语法文件就会触发 CORS**（见第 5 节）。

### 2.2 ink / inkjs —— 如果将来要做重分支叙事

| 项 | 内容 |
|---|---|
| 仓库 | `github.com/inkle/ink`（原版，C#）、`inkle/inkjs`（JS 移植） |
| 协议 | **MIT** |
| 依赖 | 零依赖，全浏览器 + Node 可用 |
| 背景 | inkle 工作室用它做了《80 Days》《Heaven's Vault》等商业作品 |

**能力**：一套专门写交互叙事的脚本语言，支持变量、条件、循环、函数、状态。**编辑器和运行时分离**——用 inklecate 编译器把 `.ink` 编成 json，运行时（约几十 KB）喂 json 就能跑。

**它比 Tracery 强在哪**：Tracery 只能生成句子，ink 能写**真正的分支剧情 + 状态耦合**（「如果你之前拿过钥匙，这里才会多出那个选项」）。

**它比 Tracery 麻烦在哪**：
- 需要引入一个**编译步骤**（写 `.ink` → 编译成 json）。这直接违反 GDD「零构建」的约束。
- 运行时加载 json 会触发 CORS（除非把 json 内联进 js 里）。

**判断**：**第一版不用，Phase 3 再考虑**。理由：3-5 分钟的单局、5-7 个节点，用自研的状态机 + Tracery 足够。引入 ink 的编译链是过度工程。

### 2.3 A Dark Room —— 不是工具，是体验标杆

| 项 | 内容 |
|---|---|
| 仓库 | `github.com/doublespeakgames/adarkroom` |
| 规模 | 约 8,285 stars / 1,787 forks |
| 形态 | **纯 JS + CSS + HTML，静态无后端，23 种语言（含简繁中文），MPL-2.0** |
| 玩法 | 纯文字 + 数字，无图形。从「醒过来。头疼。视线模糊。来把火生上。」开始，逐渐展开资源采集、探索、战斗 |

**它对《日课》的价值不是代码，是三点心法**：

1. **纯文字能做到什么程度**——它证明了「没有图形也有沉浸感」，只要文本节奏和因果反馈足够紧。这是《日课》选择文字肉鸽的信心来源。
2. **开场的写法**——第一句只有一个动作、一个感官、一个动机。**我们的 run 开场应该照这个标准写**，而不是先介绍世界观。
3. **它的源码可直接读**——MPL-2.0（文件级 copyleft），想抄一小段逻辑（如资源产出曲线、时间推进器）在协议上是允许的。

### 2.4 Novel.js —— 知道它存在就行

MIT，轻量文字冒险引擎，支持条件显示、背包、概率选项、存读档。**但作者自己标了「development has pretty much been halted」**，且**明确说明「直接双击打开 index.html 不工作」**（因为要 fetch json）。不值得投入。

## 3. 素材（美术 / 图标 / 字体 / 音效）

### 3.1 图标与 UI —— 优先用 CC0，避开署名义务

| 来源 | 内容量 | 协议 | 是否需署名 |
|---|---|---|---|
| **Kenney**（kenney.nl） | **60,000+ 资产 / 200+ 包**，含 UI Pack（430 个元素，含九宫格边框）、Input Prompts（手柄/键鼠图标）、Roguelike 角色 | **CC0** | **不需要** |
| **Game-icons.net** | **4,000+ 矢量图标**，特别适合技能图标、天赋树、UI 按钮 | **CC BY 3.0** | **需要署名** |
| OpenGameArt | 数千，质量参差 | 逐项不同（CC0 / CC-BY / CC-BY-SA / GPL） | 看具体项 |
| Iconduck / Iconfont（阿里） | 合集形式 | 多为 MIT / CC，需逐项筛 | 看具体项 |
| Craftpix freebies | 成套 UI | 自有协议：可商用、免署名、**禁止转售、禁止用于 AI 训练** | 不需要 |

**《日课》的建议用法**：
- **UI 框架元素（面板、按钮、九宫格边框）→ Kenney**。CC0 无义务，风格统一，且明确支持「九宫格拉伸」——手机分辨率碎片化，这个特性很关键。
- **属性图标 / 词条图标 → Game-icons.net**。4,000 个矢量图标够用很久。**但必须在关于页写一行署名**（CC BY 3.0 的唯一要求，一行 credits 即可满足）。
- **⚠️ 不要从 Habitica 拿素材**——它的美术是 CC-BY-NC-SA（禁商用 + 传染性 share-alike）。
- **UI 铁律（来自资料）**：一切面板都用九宫格切图（一张整图拉伸会变形）；**正文不小于 14px，像素字体必须整数倍缩放**，否则手机上看起来是坏的。

### 3.2 中文字体 —— 这里有个会毁掉 PWA 的坑

| 字体 | 协议 | 气质 | ⚠️ 体积 |
|---|---|---|---|
| **思源宋体** Source Han Serif | OFL 1.1 | 宋体，横细竖粗，有书卷气 | 完整字库，很大 |
| **思源黑体** Source Han Sans | OFL 1.1 | 黑体，规整百搭 | 完整字库，很大 |
| **霞鹜文楷** LXGW WenKai（约 25.6K stars） | OFL 1.1 | **楷书笔意，文艺、手写感，介于宋体与现代感之间** | **单字重约 25MB** |
| **得意黑** Smiley Sans（约 14K stars） | OFL | 有棱有角，视觉冲击强 | 较小 |
| 朱雀仿宋 | 开源 | 仿宋，稀有的开源仿宋 | — |
| 站酷系列 / 阿里巴巴普惠体 | 企业免费商用授权 | 黑体/装饰 | — |

**《日课》是「现代都市异闻」题材，字体选择有个明确答案**：

- **标题/事件正文用衬线或楷体**（思源宋体 / 霞鹜文楷）——异闻怪谈的味道靠字形撑，黑体太"科技感"了
- **UI 数字和标签用黑体**（思源黑体 / 系统字体）——可读性优先

**⚠️ 25MB 字体的正确用法**：

1. **绝不引入完整版**。手机 PWA 首屏加载 25MB 是灾难级的。
2. 三条路（按推荐度）：
   - **用系统字体兜底 + 只对标题子集化**——标题用到的字不超过 200 个，子集化后可能只有几十 KB
   - **用 Web 安全字体栈**——`Georgia, "Songti SC", "SimSun", serif`，零体积。iOS 有 Songti SC，Android 会退化
   - **用 Lite 版 / Screen 版**（霞鹜文楷官方提供了这两个变体），但依然要评估
3. 建议**先用系统字体栈做出来，字体美化留到最后**。

### 3.3 音效 —— 参考 hakai 的做法：不装任何音频文件

hakai-protocol-v2 **一个音频文件都没有**，所有音效（点击、导航、打卡完成、取消勾选、升级、Boss 受击、开场音）**全部用 Web Audio API 实时合成**。

**这对《日课》是极佳的方案**：
- 零体积（GDD 的 MVP 里本来就没提音效，但「即时结算反馈」如果有声音会强很多）
- 零协议风险（不用找音效素材、不用担心授权）
- 零网络依赖（符合出差场景）

**如果要真的音效素材**：Freesound（可按 CC0 过滤）、Sonniss GDC Audio Archive（每年 GDC 放出几十 GB 免费包，允许商用）、Incompetech（背景音乐，CC-BY 需署名）。

## 4. 工程组件

### 4.1 ⭐ 多文件零构建（hakai 的做法）—— 建议采纳

《日课》现在是**单文件 `index.html`**。这个选择在起步阶段是对的，但已经暴露出问题（同一文件多轮编辑冲突、改一处难定位）。

hakai 给出了一条**更好的路**：

```
index.html          ← 只做外壳，按顺序 <script> 引入
style.css
engine.js           ← 状态机 + 渲染 + 数值（约 2000 行）
content.js          ← 事件骨架 / 词条 / 解锁点（纯数据，无逻辑）
systems.js          ← 留存系统，包裹引擎函数而非改它
sw.js
```

**它的三个关键属性**：
1. **依然零构建、零依赖**——不需要 npm、不需要打包器，双击 `index.html` 就能跑（只要不用 `type="module"` 和 fetch）
2. **职责分离**——改内容不动逻辑，改逻辑不动内容
3. **可增量改造**——新功能写成新文件，用 wrap 挂上去，出问题就整个文件删掉

**建议**：下一个迭代把 `index.html` 拆成上面这个结构。**注意用普通 `<script>` 标签而不是 `type="module"`**，否则 `file://` 协议下会因 CORS 直接报错。

### 4.2 存储选型

| 方案 | 容量 | 适用 | 判断 |
|---|---|---|---|
| **localStorage**（当前用的） | 约 5MB，同步 API，只能存字符串 | 当前数据量（打卡记录 + 存档）完全够 | **继续用。不要过度设计** |
| IndexedDB / **Dexie.js** | 单域名数百 MB，异步，支持复杂对象和索引 | 数据量大或要复杂查询时 | **暂时不需要**。除非将来存 AI 生成的全部文本历史 |
| absurd-sql（sql.js + IndexedDB 后端） | 大 | 想在浏览器里跑真 SQLite | **明确不需要**，纯属炫技 |

**但要提醒**：localStorage **在 `file://` 协议下行为不稳定**（部分浏览器把它当 opaque origin 隔离，清缓存/换路径就可能丢）。所以现在的 **JSON 导出/导入功能是刚需，不是可选项**——这一点 GDD 已经识别到了，坚持做。

### 4.3 其他值得留意的

- **`lifeup-mcp`**（社区项目）：证明了「外部 LLM 通过 SDK 读写习惯应用数据」这条路是通的，对应 GDD 附录 A 的 AI 叙事映射方案
- **`be5invis/Sarasa-Gothic`（更纱黑体，约 12K stars）**：如果将来需要中英文混排且对比例敏感，这是开发者圈的标准答案
- **Nerd Fonts / Fira Code**：如果 UI 里有代码风格的排版需求

## 5. 必须避开的坑（清单）

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| 1 | 抄 Habitica 的美术资产 | **CC-BY-NC-SA，禁商用 + 传染性** | 只用 Kenney（CC0）和 Game-icons（CC BY + 署名） |
| 2 | 抄 Habitica 的代码 | **GPL v3 传染**，你的项目会被要求同样开源 | 只读思路，不复制代码 |
| 3 | 引入 25MB 中文完整字库 | 手机 PWA 首屏直接崩 | 系统字体栈兜底；标题子集化；美化押后 |
| 4 | `file://` 下用 `type="module"` 或 fetch 加载 json | **CORS 报错，双击打不开** | 用普通 `<script>`；数据内联进 js；或起本地服务器 |
| 5 | 引入 ink 的编译链 | 破坏「零构建」约束，增加出差场景的失败点 | 第一版不上；用状态机 + Tracery |
| 6 | 连击按本地午夜算、用 UTC 格式化 | **「今天完成了但连击是 0」**（hakai 的真实 bug） | 日界判定与格式化必须用同一时区基准 |
| 7 | 随机奖励可被"取消再勾"刷 | 经济崩坏、玩家自己都觉得没意思（hakai 专门防了） | 每个任务每天只 roll 一次，记录在案 |
| 8 | 每日目标可刷新重掷 | 玩家会刷到想要的那个，机制失效 | 按日期确定性抽取（hakai 的 Daily Directive 做法） |
| 9 | 新用户默认任务太多 | 第一天就清不空 → 第二周放弃 | **起步只默认开 5 项**（the-forge 的答案） |
| 10 | 只做「打卡→攒积分」的长链反馈 | 反馈链太长，等于没有反馈 | **保持即时结算**（这是《日课》已有优势，别丢） |

## 7. 建议的复用方案（分三档）

### 第一档：直接抄（零风险，省一周工作量）

| 来源 | 抄什么 |
|---|---|
| hakai-protocol-v2 | **Streak Shields 的数值**（7天1个/上限3/自动消耗）、**掉宝防刷**（每任务每天 roll 一次）、**每日目标确定性抽取**、**Proximity Scan（显示最近解锁距离）**、**App Badge**、**多文件零构建结构**、**wrap 式增量改造 + 降级保护**、**Web Audio 合成音效** |
| the-forge | **打开即「今天」，什么都没有**、**起步默认 5 项**、**用时间计量代替勾选框计量**、**打卡可撤销** |
| Tracery | 直接引入（Apache 2.0），用于事件文本渲染 |
| Kenney | UI Pack（CC0） |
| Game-icons.net | 属性/词条图标（CC BY，关于页署名） |

### 第二档：借鉴改造（需自研，中等成本）

| 来源 | 借鉴什么 |
|---|---|
| hakai Rebuild Protocol | 「连漏多天 → 给复苏加成」——**GDD 里缺这条，建议补进免死金牌旁边** |

### 第三档：自研（无参考，这是核心壁垒）

- **精力 → 肉鸽 run → 积分** 这条中间链
- **属性成长 → 游戏内选项与世界扩张**（现实自律 → 能力扩张）
- **支线任务的准入校验**（完成标志字段强制）
