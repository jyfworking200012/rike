# 开源轻型小游戏调研

> 目的：为「作息坚持的奖励机制」寻找可替换的现成开源游戏
> 调研日期：2026-10-19
> 数据来源：GitHub REST API 实时抓取 + 本地实际部署实测
> 说明：所有 star / license / 更新时间为**本次抓取的真实值**，非记忆值

---

## 一、筛选标准（先立标准，再谈推荐）

任何候选必须先过这七道门，否则不值得考虑：

| # | 标准 | 权重 | 理由 |
|---|---|---|---|
| 1 | **纯静态**，无后端/数据库 | 硬性 | 要部署在 GitHub Pages，单机自用 |
| 2 | **手机可玩**，触屏友好 | 硬性 | 主力设备是手机 PWA |
| 3 | 单局时长 1–5 分钟，或**可分段进行** | 硬性 | 奖励必须在碎片时间消耗 |
| 4 | 有本地存档 | 硬性 | 断网可玩、进度不丢 |
| 5 | License 允许个人修改自用 | 硬性 | 需要改造成打卡入口 |
| 6 | 开源 + 社区活跃度 | 高 | 出问题能查到、能修 |
| 7 | **玩法本身被市场验证过** | 高 | 不能靠"我觉得好玩" |

第 7 条是这次调研的核心分歧点：star 数只证明"开发者喜欢"，不证明"玩家觉得好玩"。所以优先考虑**有商业发行版**的项目（上过 App Store / Steam）。

## 三、逐个点评

### 1. A Dark Room —— 最契合，但有个大坑

**它是什么**：极简文字冒险。开局只有一句话 `awake. head throbbing. vision blurry. come light the fire.`，全程靠文字推进。从生火、砍柴、抓陷阱，到建村庄、组队远征、发现真相。

**为什么最契合**：
- **有商业发行**：iOS / Android / Steam 正式上架 → 玩法被市场验证，不是"开发者自嗨"
- 官方支持 **23 种语言，含简体中文**（URL 加 `?lang=zh_cn`）
- 纯静态，无后端，`index.html` 双击就能跑
- 核心循环是**「挂机积累资源 → 消耗资源探索」**，天然适配"每天来看一眼"

**实测发现的问题（重要）**：

仓库的 `index.html` **没有 `<meta name="viewport">`**，`css/main.css` 里是 `width: 700px` 固定宽度 + `float: left` 多栏布局，**没有任何 `@media` 断点**。

我在 390px 视口下实际截图，结果如图：所有元素挤在左上角，文字溢出，界面完全不可用。

> 也就是说：**A Dark Room 的"手机版"是 App Store 上的独立打包版本，不是这个 Web 仓库。**
> 网上文章说它"响应式、手机可玩"，指的是官方 App，不是开源代码。

**适配成本**：需要重写整个 CSS 布局层（房间面板 / 日志区 / 状态栏 / 浮动按钮），改成移动端单栏或底部标签切换。保守估计 3–5 小时，且要重新测一遍所有交互。

**结论**：玩法骨架最合适，**但不能直接用，必须改造**。

---

### 2. 2048 —— 最稳，但和作息无关

**实测结果**：390px 视口下**完美适配**。有完整 viewport meta，CSS 里有 `@media (max-width: 520px)` 断点，网格自动缩放，触屏滑动原生支持。

- 13,442 stars，MIT，最经典的单机小游戏之一
- 625 KB，加载快，离线无压力
- 1–3 分钟一局，天然适合碎片时间

**问题**：它和"作息"没有任何因果关系。只能做成"今天达标了才能玩一局"——这本质上是**用游戏当门禁**，不是奖励。而且 2048 随时可以在别处玩，稀缺性为零。

---

### 3. Hextris —— 手感最好，但生命周期短

六边形俄罗斯方块，转圈消块。2,443 stars，GPL-3.0。

- canvas 自适应，手机触屏支持良好
- 上手零门槛，反馈即时，2–5 分钟一局
- 上过 Hacker News 首页，口碑不错

**问题**：反应类游戏的通病——**爽但短命**。玩两周基本就腻了，撑不起长期激励。GPL-3.0 对自用无影响，但修改版若要分发必须开源。

---

### 4. 放置类（Antimatter Dimensions / Trimps / vue-idle-game）

这类是**最被低估的方向**：放置游戏的设计前提就是"你不需要一直玩，回来看一眼就有进展"，和"每天打卡"的节奏天然同构。

- Antimatter Dimensions：411 stars 但口碑极好，有 App Store 版，MIT
- Trimps：286 stars，放置类经典，GPL-2.0
- vue-idle-game：1,356 stars，中文，刷装备玩法

**问题**：star 数都不高，社区小，出问题不好查。且这几个我还没实测手机适配，需要验证后才能给结论。

## 四、关键判断

### 判断一：换游戏，解决不了「坚持」问题

老大自己的数据摆在这里：

- 11 天打卡 26/77 = **33.8%**
- 满勤 **0 次**
- 6 局游戏全在前 2 天
- 兑换只有 1 次

这个分布说明：**不是游戏不够好玩，是"打开 App 的动力"在第 3 天就断了**。换一个更好玩的游戏，只会让人更想玩游戏，不会让人更想早起。

上次失败的根因（我复盘过）是：**代币和奖励之间没有因果**。换成任何现成游戏，只要还是"打卡 → 攒币 → 玩游戏"，就是同一个结构，会以同样的方式失效。

### 判断二：真正值得抄的是「因果结构」，不是游戏本身

A Dark Room 值得抄的**不是它的文字**，是它的资源链：

```
点火 → 需要木头 → 需要去砍 → 砍柴耗时 → 需要建陷阱捕兽 →
需要皮毛换钱 → 需要建棚屋 → 需要更多人手 → ...
```

每一步都由上一步**直接产生**，没有"代币"这个中间环节。

把这个结构嫁接到打卡上，就变成：

```
早起 → 天亮得早 → 屋外多出一段时间
锻炼 → 体力 +1 → 能走更远的路
戒断 → 心志 +1 → 能扛住更糟的遭遇
```

**打卡动作本身就是资源产出**，不经过代币。这才是上次和上上次都没做到的事。

### 判断三：三条路的投入产出比

| 路线 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| **A. 嫁接 A Dark Room** | 下载源码 → 重写 CSS 移动适配 → 把 7 项打卡映射成资源产出 | 1–2 天 | 授权合规没问题（MPL-2.0 允许修改）；改造后可能失去原版节奏 |
| **B. 接一个成品短局** | 2048 / Hextris 直接部署，加一层"达标才解锁"的门禁 | 半天 | **游戏与作息无因果**，大概率重蹈 v1 覆辙 |
| **C. 保留院子，做厚画面** | 现在的院子加昼夜、天气、四季、更多可建造物 | 1 天 | 老大已明确说"这个设计不行" |

**我的建议是 A**。理由是它是唯一同时满足「玩法被验证过」和「打卡动作有因果」的选项。

但要说清楚代价：A 是我改造别人的游戏，改造完的体验**不会等于原版 A Dark Room**，而且第一次做完大概率还要调。
