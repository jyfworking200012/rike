# 《镇志》设计稿 v7 — AI 接入层

> 本稿只处理一件事：**把 AI 从「文案皮肤」提升为「事件设计师」，同时保证数值永远不失控。**
> v5 / v6 已确认的数值体系（九阶门槛、断链衰减、衙门折扣、三类事件占比）**全部不变**。

---

## 0. 一句话

**AI 决定「发生什么事、有哪几个选择、话怎么说」；程序决定「成功率多少、给多少资源、扣多少东西」。中间靠一套语义闭集隔开。**

用户要的「更大自主权」和系统要的「数值可控」，唯一的共处方式就是**把事件拆成"语义"和"数值"两层，AI 只碰上层**。

---

## 1. 权限矩阵（这是本稿的核心表）

| 内容 | 谁决定 | 说明 |
|---|---|---|
| 事件骨架（发生什么） | **AI（丙级）/ 程序（乙、甲）** | 见 §2 分层 |
| 出现在什么人身上 | **AI** | 只能用镇上现有的人 + 程序给的新 NPC 池 |
| 发生在什么地方 | **AI** | 必须是已解锁的地点 |
| 有几个选项 | AI（2–3 个） | 少于 2 或多于 3 → 丢弃重生成 |
| 选项的**意图类型** | AI 只能从 **16 个闭集**里选 | 越界即判废 |
| 选项的文案 | **AI 全权** | 随便写 |
| **成功率** | 程序 | AI 无字段可写 |
| **奖励/消耗数量** | 程序 | AI 无字段可写 |
| 事件等级（丙/乙/甲） | 程序给定候选池 | AI 可在池内挑，不能越级 |
| 是否引用记仇 | 程序强制要求 | AI 必须标注 `uses_grudge`，否则重试 |

**AI 的输出里根本没有"数字"这个字段。** 不是"不许填"，是**协议层不存在**。这是最可靠的一道锁——提示词可以被绕过，缺失的字段不行。

## 2. 三层生成：AI 权力最大的地方，恰好最安全

| | 骨架 | 人·地 | 选项 | 文案 | 数值 | 占比 | AI 自主 |
|---|---|---|---|---|---|---|---|
| **丙级**（村民小事） | **AI 全靠自己** | AI | AI | AI | 程序 | 60% | **95%** |
| **乙级**（外来·中等灾害） | 程序从 46 骨架里抽 | **AI 换人换地** | AI | AI | 程序 | 30% | **55%** |
| **甲级**（瘟疫·建交·救邻城） | 程序固定 12 个 | 程序 | 程序 | **AI 改写** | 程序 | 10% | **20%** |

### 为什么这样分

**丙级必须放飞。** 它不产生后果（只给 5–15 资源），是纯氛围。AI 在这里写得越怪越好——"老陈把柴劈得比平时细，说冬天要来了"这种句子，我写 200 条也写不完，AI 每天都是新的。

**乙级只能换皮。** 骨架锁死，是因为乙级有真实后果（丢资源、伤人口），结构必须可预期。但**人换掉、地换掉，同一件事就完全变样**：

> 骨架「有人病倒」
> × 苏姐 × 医馆 → **她自己倒下了，没人看病**
> × 货郎 × 镇口 → **他倒在路上，身上还压着一担货**

这就是"更多样"最便宜的来源：**换人比换事有效十倍。**

**甲级必须锁死。** 因为甲级挂在记仇链和升级门槛上。如果 AI 把"救邻城"写成"因为抢水源"，二十天后"邻城商队绕开你"就接不上了——**主线一致性 AI 保不住，只有预置能保。**

但甲级**放开文案**：骨架、选项、数值全定，AI 只负责用当前镇子的状况把这件事重写一遍。所以每次瘟疫都不重样，但机制永远算得准。

## 3. 语义闭集：16 个意图

AI 生成选项时，`intent` 只能取以下 16 个值之一。**程序靠它查表定价。**

| 组 | intent | 语义 | 典型代价 | 典型回报 |
|---|---|---|---|---|
| 救助 | `treat` | 请医、给药 | 药 | 体质↑ / 保人 |
| | `shelter` | 收留 | 肉、房位 | 人口↑ |
| | `ransom` | 付钱赎 | 钱 | 保物保人 |
| 拒绝 | `refuse` | 拒绝 | 人情 | 无（记仇+1） |
| | `expel` | 驱逐 | 人情 | 治安↑（记仇+2） |
| | `ignore` | 不管 | 损失扩大 | 无 |
| 交易 | `trade` | 正常换 | 对应资源 | 按市价 |
| | `haggle` | 压价 | 成功率 | 高则多得 |
| | `invest` | 投资 | 资源 | 延迟回报 |
| 对抗 | `fight` | 硬碰 | 治安、铁 | 大得 / 受伤 |
| | `hunt` | 追捕 | 治安 | 肉、皮毛 |
| | `gamble` | 赌一把 | 高风险 | 最高收益 |
| 开拓 | `explore` | 派人探查 | 人·时间 | 解锁地图/新事件池 |
| | `ally` | 建交 | 钱、文化 | 长期贸易 |
| | `build` | 借机建造 | 木、石 | 直接出一座建筑 |
| 牺牲 | `sacrifice` | 弃小保大 | 人口或建筑 | 保住大头 |
| | `abandon` | 放弃 | 资源 | 保住人 |

**每个 intent 配一张固定价目表**，量级由 `tier × 当前镇阶` 决定。所以 AI 写了「强留他做短工抵药钱」，程序查 `expel`，扣的就是 `expel` 该扣的，不会因为 AI 写得可怜就少扣。

## 4. 成功率：唯一让 AI 参与、但由程序结算的公式

```
安全选项（safe）           = 100%，不进公式
其余：p = base(risk)
        + 5 × 相关建筑等级
        + floor(文化 / 10)
        + floor(治安 / 15)
        − 断链惩罚
        clamp(5, 95)

base：normal 65 / bold 40
```

| 场景 | 算出来 | 为什么 |
|---|---|---|
| 荒村·bold·全 0 | 40% | 新手期冒险就是难 |
| 集镇·normal·建筑Lv2·文化50·治安35 | 65+10+5+2 = **82%** | 中期刚好"有把握但不保险" |
| 断链 3 天再掷 bold | 40−18 = **22%** | 断链惩罚落在赌注上最痛 |
| 都会·bold·满配 | 40+35+35+13 = **95%（封顶）** | 再怎么堆也留 5% 翻车 |

**注意**：断链惩罚同时作用于产出**和**成功率。产出低只是慢，赌注输是痛——这条让"连续打卡"在后期有真实价值，而不只是多收几袋米。

**连输两次补偿**（v4 定过，保留）：同一天第二次、第三次事件各 +20%，界面标「时来运转」。上限 +40%。

## 5. 生成成本、延迟与兜底

| 级别 | 什么时候生成 | 延迟容忍 | 失败兜底 |
|---|---|---|---|
| 丙 | **打开页面时批量预生成 5 天量**，缓存 | 0（翻到就是现成） | 预置小事池 40 条 |
| 乙 | 事件触发时实时生成 | **3 秒**，超时即用预置骨架 | 46 骨架原始版本文案 |
| 甲 | 打开页面时生成（一天只有 1 件） | 5 秒 | 预置 12 件原文案 |

**调用量估算**：丙 5 天 × 1.5 件 ≈ 8 次批次 / 5 天；乙约 3 次/周；甲约 1 次/6 天 → **平均每天 3–5 次**。DeepSeek 量级上可忽略。

**断网 / 无 Key / 超时**：全部走预置，**不弹错误、不让你等、不提示"AI 不可用"**。你不需要知道 AI 挂没挂。

## 6. 六道校验（AI 输出必须全过）

```
① JSON 结构完整（text / options[2-3] / actor / place / tier / uses_grudge）
② 每个 option.intent ∈ 16 闭集
③ 选项数 2–3
④ 正文 40–160 字，选项文案 ≤ 14 字
⑤ 人物 ∈（当前居民 ∪ 新NPC池），地点 ∈ 已解锁地点
⑥ 画风黑名单：无现代词汇、无科技、无性/暴力描写、无现实品牌/人名
```

任一失败 → **重试 1 次** → 再失败 → **降级预置**。
校验器只有 120 行逻辑，但它是整个 AI 接入的安全阀。

## 7. 画风护栏（写进 system prompt 并且二次过滤）

| 锁定的 | 内容 |
|---|---|
| 时代 | 民国山村感，无电力、无机械、无货币符号 |
| 材质 | 纸上墨迹，克制的白描，不用形容词堆砌 |
| 语气 | 短句、少感叹、不煽情。**越平淡越吓人** |
| 禁止 | 现代科技、外来语、网络用语、血腥描写、色情、政治、真实人名 |

**这一条我特别坚持**：AI 的默认文风是"网文味"，一放开就会写出"他眼中闪过一丝不易察觉的狠厉"。这类句子会把这个游戏的气质毁掉。护栏不是限制多样性，是保证多样性还在同一个世界里。

## 8. AI 需要知道的镇子（状态摘要注入）

每次调用带一段约 200 token 的摘要，AI 才不会写出"集市里空无一人"但你有 12 个人在赶集这种矛盾：

```
第23天 · 集镇 · 人12/14
木180 石60 肉40 铁22 药9 钱240 文化62 治安48
建筑：木场Lv2 猎屋Lv2 医馆Lv1 私塾Lv2 铁铺Lv1 集市Lv2 灯塔Lv1
在办：无
记仇：赶走流民(第11天·重2)
近事：第21天商队被劫
```

## 9. 记仇怎么交给 AI（这条最容易被写坏）

记仇表 `grudges[]`：`{ who, what, day, weight }`，weight 1–3。

规则：

1. 每次生成，程序把 **weight ≥ 2 的记仇**注入 prompt
2. AI 输出必须带 `uses_grudge: true|false`
3. **若存在 weight ≥ 2 的记仇，而 AI 返回 false → 判废重试**（最多 1 次，仍 false 则降级预置）
4. weight ≥ 3 → 强制升级为乙级事件（你不能再让村长家代办）

第 3 条是让"记仇"真的会发生，而不是写在文档里。**不校验的话，AI 十次有八次会忘。**

## 10. 「路多 → 外来事件多」怎么接进去

| 规模变量 | 影响 | 落到哪 |
|---|---|---|
| 商道建筑等级 N | 外来事件权重 `20% + 8%·N` | 事件池配比 |
| 人口 P | 丙级事件触发量 `+8%/10人` | 丙级批量生成条数 |
| 城镇阶 | 甲级可用池扩大 | 程序给的 tier 候选 |

**但你能看到的量不变**——多出来的全被衙门吃掉（v6 已定）。所以规模上涨带来的不是负担，是**"镇子在运转"的感觉**。

## 12. 我还不确定的三处

1. **丙级全 AI 生成会不会"太飘"**——AI 容易写出无意义的小事。缓解：给 40 条预置当"文风样例"塞进 prompt（few-shot），比写规则有效。
2. **3 秒超时对中文长文本可能不够**——实际测试可能要到 5 秒。要不要接受"等 5 秒看一段好文字"？我倾向接受，但只在乙级。
3. **甲级 AI 改写会不会偷偷改掉选项语气**——比如把"稳赚"的选项写得像坑。所以甲级的选项文案**由 AI 写、但和 intent 绑定**，写歪了你会选错。这是真实风险，需要 3 轮人工比对。
